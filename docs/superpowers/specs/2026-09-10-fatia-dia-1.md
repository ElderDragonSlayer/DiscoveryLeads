# Fatia Dia 1 — a menor coisa que já lista leads

**Data:** 2026-09-10
**Depende de:** `2026-09-09-discoveryleads-backend-design.md`

O objetivo desta fatia é ter **leads reais num CSV ordenado** o mais rápido possível.
Não é um protótipo descartável: cada peça aqui é a versão mínima de um componente
que a spec já descreve, e cresce para a versão completa sem reescrita.

## Entregável

```
python -m discoveryleads buscar \
    --nicho "salão de beleza" \
    --cidade "Goiânia" \
    --raio 5000 \
    --max-chamadas 40 \
    --saida leads.csv
```

Colunas do CSV: nome, telefone, endereço, **faixa (T0–T3)**, elegibilidade, motivo,
plataforma do site, URL, rastreamento detectado, avaliações, nota, link do Maps,
link do WhatsApp pronto.

## As quatro peças

| # | Peça | Depende de chave? |
|---|---|---|
| 1 | `site_classifier` + `tracking_detector` | **Não** — começar por aqui |
| 2 | `places_discovery` simples | Sim, Places API |
| 3 | Elegibilidade + faixas T0–T3 | Não |
| 4 | Export CSV | Não |

A peça 1 é o diferencial do produto e não depende de nada externo. Construir ela
primeiro significa trabalho útil enquanto a chave do Google não existe.

### 1. `site_classifier` + `tracking_detector`

Recebe uma URL, devolve sinais. Sem API, sem custo.

- resolve DNS, segue até 5 redirects, mede status e tempo de resposta
- classifica `site.plataforma` no enum da seção 5 da spec:
  `canva` · `agregador` · `google_sites_extinto` · `wix` · `wordpress` · `shopify` ·
  `loja_integrada` · `proprio` · `quebrado` · `ausente`
- extrai contatos: `wa.me`, `mailto:`, links sociais
- extrai defeitos vendáveis: viewport ausente, título ausente, meta description
  ausente, HTTPS inválido, placeholder não editado
- detecta rastreamento: Meta Pixel, Google Ads, GA, GTM, heatmap, TikTok Pixel

**Testes com fixtures reais desde a primeira linha.** HTML de verdade em
`tests/fixtures/sites/`, um arquivo por caso. É a peça onde falso positivo custa
credibilidade na frente do cliente.

### 2. `places_discovery` simples

Text Search com paginação, raio único, field mask enxuta (`websiteUri`,
`nationalPhoneNumber`, `userRatingCount`, `rating`, `businessStatus`, `types`,
`priceLevel`, `location`, `formattedAddress`, `displayName`).

`--max-chamadas` é **obrigatório**, não opcional: é o freio que substitui o
`cost_ledger` enquanto ele não existe.

### 3. Elegibilidade + faixas

Regras exatamente como a seção 6 da spec. Elegibilidade com motivo em texto, faixas
T0 a T3, sem cálculo de valor nem de confiança ainda.

### 4. Export CSV

Direto, síncrono.

## O que NÃO entra hoje

Fila e workers · API web · SSE · ladrilhamento adaptativo · Alembic · resolução de
identidade completa · Instagram · PageSpeed · dossiê de abordagem · confiança.

## Substituições táticas (descartáveis sem retrabalho)

| Componente final | Substituto de hoje |
|---|---|
| Fila `jobs` | execução sequencial; `asyncio.gather` limitado só nos fetches de site |
| Ladrilhamento adaptativo | Text Search paginado, raio único |
| `lead_identities` | dedupe por `place_id` |
| Alembic | um `schema.sql`, que amanhã vira a primeira migração |
| API FastAPI | linha de comando |
| `cost_ledger` | contador em memória com teto `--max-chamadas` |

## Spikes: dois deixam de bloquear

- **S1** (Instagram sem login) — irrelevante hoje: Instagram não entra na fatia.
- **S3** (retenção do cache do Places) — irrelevante hoje: o script grava **só sinais
  derivados**, nunca o payload cru do Google. Não existe cache para ter prazo.
- **S2** (preço do Places) — resolvido naturalmente ao criar a chave.
- **S4** (`*.negocio.site` / `*.business.site` hoje) — ainda vale, e é rápido:
  decide a regra de `google_sites_extinto`.

## Definição de pronto

Uma busca real, num nicho e num bairro, produz um CSV em que **o operador olha as
dez primeiras linhas e reconhece leads que valem uma ligação**. Se não reconhecer,
o problema está na classificação ou nas faixas, e é isso que se ajusta antes de
seguir para a etapa E4 da spec.
